## Why

Writing a `type` by hand and then a Zod schema that describes the same shape creates two definitions that agree today and drift the first time one of them is edited, with the compiler unable to notice. Define the schema once and derive the type with `z.infer`, so the runtime check and the static type cannot disagree. Input variants come from the schema too, through `omit`, `pick`, and `partial`.

## Message

hand-written type duplicates a schema; derive it with `z.infer`

## Bad

```ts
// BAD: two definitions of the same shape that nothing keeps in sync
type Item = {
	id: string;
	name: string;
};

const itemSchema = z.object({
	id: z.string(),
	name: z.string(),
});
```

## Good

```ts
const itemSchema = z.object({
	id: z.string(),
	name: z.string(),
});

type Item = z.infer<typeof itemSchema>;

const createItemSchema = itemSchema.omit({ id: true });

type CreateItemInput = z.infer<typeof createItemSchema>;
```
